# 软件需求规格说明书（SRS）

## 1. 范围
建设“学生实训室选组选拔系统”，替代人工汇总 Excel/邮件确认，支撑双向选择、分轮录取、统筹调剂与结果公示。

## 2. 用户与角色
| 角色 | 核心诉求 |
|---|---|
| 学生 | 查看项目/名额，填报最多3个平行意向，参加面试，查看拟录取并唯一确认，参与补录/服从调剂。 |
| 导师/实训室负责人 | 维护项目介绍与名额，录入/校准面试评分，查看拟录取/递补/调剂候选。 |
| 管理员（教务/学生工作组，含监督与申诉受理） | 发布轮次与时间节点、维护实训室/导师、运行选拔与调剂、公示名单、处理实名异议、查看审计日志。 |

## 3. 功能需求
### F1 基础数据
- 实训室 CRUD：名称、容量、项目方向、简介、开放日安排。
- 导师/项目 CRUD：所属实训室、招录名额、考核要求。
- 轮次 CRUD：宣讲、开放日、填报、面试、确认、补录、调剂、公示起止。

### F2 志愿填报
- 学生最多填报3个平行导师意向，不区分先后。
- 必填：是否服从实训室内部调剂、是否服从全院跨实训室调剂。
- 截止后锁定；系统故障时以日志与时间戳复核。

### F3 面试与评分
- 以实训室为单位统一面试，所有报名学生均须参加。
- 评分维度：学习态度与动机25、逻辑思维与表达20、编程/专业基础35、时间投入与协作20，总分100。
- 结论：拟录取 / 递补 / 内部调剂候选 / 不推荐；须留痕。

### F4 拟录取确认
- 仅1个拟录取意向：自动确认。
- ≥2个拟录取意向：学生必须在窗口内选择唯一去向。
- 逾期未确认：视为放弃，空出名额进入递补。

### F5 分轮补录
- 公布剩余名额与可报范围；未录取学生重新填报；统一面试、双向确认、顺位递补；支持第二轮、第三轮。

### F6 统筹调剂
- 三轮后剩余名额进入全院调剂池。
- 优先级：实训室内部调剂 → 全院跨实训室调剂 → 约谈未服从调剂学生并最终统筹安置。

### F7 公示与入组
- 公示1天；实名异议与复核；无异议后正式入组并进入 AI+PBL 实训。

## 4. 非功能需求
- 安全：密码哈希、最小权限、参数校验、防越权、敏感信息脱敏、操作审计。
- 一致性与并发：确认锁定、名额扣减、递补触发需事务或幂等设计。
- 性能：填报/确认窗口支持至少 1000 并发提交；核心查询 < 500ms（按校级规模估算）。
- 可审计：所有名单生成、改分、确认、递补、调剂动作可追溯。

## 5. 约束与假设
- 学院已有统一身份认证；MVP 可用 DEMO_MODE 演示。
- 时间不晚于：宣讲10月29日14:00；填报11月2日08:00-12:00；面试11月2日12:00-11月3日17:00；确认11月4日08:00-12:00；补录11月4日12:00-11月5日17:00；调剂11月6日08:00-12:00；公示1天（以正式通知为准）。
