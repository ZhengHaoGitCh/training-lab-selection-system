# 学生实训室选组选拔系统 PRD

> 版本：v1.0 ｜ 日期：2026-11-09 ｜ 状态：已确认（学生 / 老师 / 管理员三角色）
> 参考流程海报：对话附件 `mmexport1794203798244.jpg`（8 步流程图，本文附录 A 已转写为文字）

## 项目概述

一句话：把“学生实训室选组选拔”从 Excel 汇总、群通知和线下签字，变成一套**三角色在线协同、全流程可追溯**的 Web 系统。

系统覆盖：集中宣讲 → 实训室开放日 → 平行志愿填报 → 统一面试评分 → 拟录取确认 → 分轮补录 → 统筹调剂 → 结果公示与入组。核心价值是把“名额、分数、志愿、确认、递补”这些容易出错的状态收进数据库，让每一次改分、确认、调剂都有审计记录。

## 目标用户

| 角色 | 使用人 | 现在的问题 | 系统要解决什么 |
|---|---|---|---|
| 学生 | 参与选组的本科生（演示账号 `2023001`~`2023008`） | 实训室信息分散在宣讲和群里；志愿靠表格收集；面试后不知道进度；错过确认时间就失去名额 | 一处查看实训室/导师/名额；最多 3 个平行志愿；实时看面试、拟录取、补录、调剂状态；在线唯一确认；实名申诉 |
| 老师（导师） | 各实训室导师（演示账号 `t1001`~`t1007`） | 报名名单靠教务转发；评分标准不统一；名额余额和录取结果要反复问 | 只看报自己的学生；按统一四维标准在线评分；实时看名额余额、拟录取/递补/确认情况 |
| 管理员 | 教务/学生工作组（演示账号 `admin`） | 手工排序易错；名额扣减、逾期、递补、调剂难追踪；公示与异议靠线下 | 维护实训室/导师/轮次；录入或校正面试分；运行选拔（支持预演）；逾期释放、补录、调剂、约谈安置；发布公示、处理申诉、查看审计 |

> 监督/申诉受理不再单列账号，相关查看与处理能力并入管理员；导师跨实训室的协同评分、仲裁暂不做（见“暂不做”）。

## 核心功能

1. **流程总览与信息发布**
   公开首页展示 8 步流程、实训室方向与导师名额、各轮次时间窗、已发布公示；学生无需登录即可了解全貌。
2. **平行志愿与服从调剂**
   学生在填报轮次内最多选择 3 个导师志愿，**不区分先后**；同时设置“服从实训室内部调剂”“服从全院跨实训室调剂”两个开关；截止后只读。
3. **统一面试与四维评分**
   老师按“学习态度与动机 25 + 逻辑思维与表达 20 + 编程/专业基础 35 + 时间投入与协作 20”在线打分，总分 100；**老师只能给填报了自己志愿的学生评分**；改分留痕。
4. **选拔与拟录取确认**
   管理员按导师分别排序（总分降序、学号升序打破平局），产出拟录取/递补/内部调剂候选/不推荐；支持 `dry-run` 预演。学生收到 1 个拟录取时自动确认，收到 ≥2 个时必须在窗口内选择唯一去向；逾期释放名额并进入递补。
5. **补录、调剂、公示与申诉**
   公布剩余名额并按顺位递补；三轮后进行统筹调剂（实训室内部 → 全院跨室 → 约谈安置）；公示 1 天，学生可实名提出异议，管理员处理并回复；所有关键动作写审计日志。

## 页面 / 模块结构

### 公共端（无需登录）

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/` | 流程总览 | 8 步流程、开放轮次提示、实训室与导师名额、时间安排、最新公示 |
| `/login` | 登录 | 学生 / 老师 / 管理员三个入口、账号密码登录、演示账号一键填充 |
| `/announcements` | 公示公告 | 已发布公示列表与正文、公示时间 |

### 学生端（`role = student`）

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/student` | 我的选组 | 当前阶段、志愿/面试/待确认数量、轮次时间轴、快捷入口 |
| `/student/intentions` | 志愿填报 | 按实训室浏览导师、最多 3 个平行志愿、两个调剂开关、提交与撤回 |
| `/student/offers` | 拟录取 | 拟录取/递补/调剂通知、有效期、单意向自动确认、多意向唯一选择 |
| `/student/appeals` | 我的申诉 | 新建实名申诉（可关联公示）、处理状态与回复 |

### 老师端（`role = mentor`）

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/teacher` | 老师工作台 | 我的实训室/名额余额、报名/已面试/待确认/已确认数量、轮次提示 |
| `/teacher/applicants` | 报名学生 | 报我的学生列表、面试总分与结论、录取状态、四维评分弹窗 |
| `/teacher/offers` | 我的名单 | 拟录取/递补/内部/跨室/约谈记录、确认状态与名额余额 |

### 管理端（`role = admin`）

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/admin` | 仪表盘 | 实训室/导师/名额/学生/志愿/面试/拟录取统计、开放轮次、最近审计 |
| `/admin/labs` | 实训室与导师 | 实训室 CRUD、导师 CRUD、名额上限校验、停用与名额进度 |
| `/admin/rounds` | 轮次 | 8 类轮次 CRUD、时间窗与开放状态 |
| `/admin/interviews` | 面试评分 | 按轮次/导师筛选、代录或校正四维分、查看结论 |
| `/admin/selection` | 选拔与录取 | 运行选拔（预演/正式）、拟录取名单、逾期释放、顺位补录、统筹调剂、约谈安置 |
| `/admin/publications` | 公示与申诉 | 新建/发布公示、处理实名申诉、入组名单 |
| `/admin/audit` | 审计日志 | 按动作筛选、查看改分/确认/调剂前后值 |

### 通用模块

- 顶部导航按角色切换；移动端折叠为抽屉菜单。
- 鉴权：JWT Bearer；未登录跳登录页；无权限显示 403；登录后按角色回到各自首页。
- 统一反馈：加载态、空状态、错误提示、提交二次确认、危险操作二次确认。

## 设计与体验要求

- **视觉来源**：沿用流程海报的气质——深藏青标题、淡蓝紫浅底、白色圆角卡片、编号流程、时间徽章；橙色只用于“面试”这一强调节点，不铺满全站。
- **色彩**：主色 `#2f6fba`；标题/正文深色 `#17324d`；页面底色 `#eef2fb`；强调橙 `#e8772e`；成功绿 `#1f7a5c`；弱化文字 `#68788f`；描边 `#dfe6f2`。
- **字体**：系统中文无衬线（PingFang SC / Microsoft YaHei / Noto Sans SC），数字统一等宽数字（`font-variant-numeric: tabular-nums`），避免时间与分数跳动。
- **布局**：内容容器最大 1200px；卡片圆角 14–16px，阴影轻；信息密度以“一屏看清当前轮次和待办”为准。
- **设备**：桌面端优先（1280–1440px），同时适配手机（390px 起）；表格在窄屏允许卡片内横向滚动，导航折叠为抽屉，触控目标不小于 40px。
- **状态表达**：待确认=橙、已确认=绿、已过期/放弃=灰、不推荐=红；状态标签必须同时有文字，不能只靠颜色。
- **关键交互**：
  - 志愿提交前二次确认，明确“最多 3 个、不分先后、截止后不可改”；
  - 多个拟录取的确认弹窗强制单选，并显示各自的实训室、名额与有效期；
  - 评分弹窗实时显示四维总分与各维度上限；
  - 运行选拔默认勾选“预演”，正式执行需要二次确认；
  - 调剂、约谈、发布公示等管理动作显示影响人数或名单摘要后再执行。

## 技术约束

- **前端**：Vue 3（`<script setup>`）+ Vite + Element Plus（中文 locale）+ Pinia + Vue Router + Axios，使用 JavaScript，不引入 TypeScript 构建链，降低课程演示时的构建故障面。
- **后端**：沿用现有 FastAPI + SQLAlchemy，统一响应 `{code, message, data}`，JWT Bearer 鉴权；不改变已有接口的行为与字段。
- **老师端**：现有后端只有 `mentor` 角色枚举而没有老师接口，需要补 `GET /teacher/profile`、`GET /teacher/applicants`、`GET/POST /teacher/interviews`、`GET /teacher/offers`，并给老师账号绑定导师档案；老师写操作仅限“给报自己的学生评分”。
- **联调方式**：开发环境 Vite 将 `/api` 代理到 `http://127.0.0.1:8000`；生产构建通过 `VITE_API_BASE` 指向后端地址。
- **权限**：路由守卫按角色拦截；接口 401 清会话回登录页；403 展示无权限页；管理员专属按钮对老师与只读角色隐藏。
- **依赖**：除 Element Plus 及其图标包外不引入重型 UI/图表库；不使用外部字体与图片 CDN，保证离线演示可用。
- **数据一致性**：名额、确认、递补以服务端为准，前端不做本地扣减；提交失败必须回滚界面状态并给出原因。

## 验收标准

1. **主线可跑通**：学生填报 → 老师评分 → 管理员预演/正式选拔 → 学生单意向自动确认或多意向唯一确认 → 管理员逾期释放与顺位补录 → 统筹调剂 → 发布公示 → 学生申诉 → 管理员回复。
2. **三角色隔离**：学生不能进入老师/管理页面；老师只能看到并评分报自己的学生；管理员专属操作（运行选拔、补录、调剂、约谈、基础数据 CRUD）不会出现在老师界面。
3. **双端可用**：1440px 桌面与 390px 手机宽度下，导航、表单、名单均可操作，无整页横向溢出；关键操作有明确反馈。
4. **构建与质量**：`npm run build` 成功；浏览器控制台无 error；后端 `pytest` 全绿；新增老师接口有越权测试。
5. **视觉接近参考**：8 步流程完整呈现，配色、圆角卡片、编号与时间徽章与海报同源，橙色仅作面试强调。
6. **可追溯**：改分、确认、逾期、补录、调剂、公示、申诉处理都能在审计日志中查到操作者与前后值。

## 暂不做的事情

- 导师跨实训室调阅、多人协同评分、评委加权与仲裁记录；
- 监督/申诉受理独立角色（能力并入管理员）；
- 学院统一身份认证 / OIDC、短信/邮件通知；
- Excel/PDF 导出、打印公示单、附件上传；
- 1000 并发下的行级锁与压测、Redis 限流；
- 深色模式、多语言、移动 App / 小程序；
- 富文本公示编辑器（当前使用纯文本 + 换行）。
